HARDENING REGRESSIONS INCLUDED
------------------------------
- approval waits survive restart without auto-approval
- hard-crash RUNNING state is converted to INTERRUPTED before auto-resume
- in-progress crash attempts are retained as interrupted step history
- immediate approval cannot race future registration
- active workflow cancellation terminates the owned run task
- re-entrant/self-cancellation cannot be overwritten by completion
- false-success workflow paths fail closed
- unknown workflow edges fail explicitly
- real async EventBus dispatch is wired through TaskRegistry
- tool transcripts preserve assistant tool_calls before tool results
- malformed/type-invalid tool arguments are rejected by JSON Schema
- final-round pending tools are not executed without a continuation turn
- verifier failure events retain exact check details
- concurrent execution verifiers use unique, cleaned artifacts
- pytest reflection requires an authoritative pytest verifier PASS
- embedding fingerprints isolate incompatible vector spaces
- sqlite-vec optimization degrades to exact fallback safely
- Redis serialization preserves event identity/correlation/trace context
- Redis inbound events are not echoed back out on overlapping topics
- OpenTelemetry instrumentation uses current spans and real parent/child traces
- asynchronously dispatched handlers continue the publish trace
- bounded worker shutdown handles queue_max < max_workers cleanly

OPTIONAL DEPLOYMENT QUALIFICATION
---------------------------------
OpenTelemetry SDK/exporter were installed and exercised against a real SDK
TracerProvider in this validation environment.

The optional `redis` and `sqlite-vec` packages were not installed here. Their
serialization, import/degradation, filtering, deduplication, and fallback paths
are covered by regression tests, but live Redis connectivity/reconnect behavior
and native sqlite-vec KNN execution remain environment-specific deployment
qualification items rather than claims made by this release validation.
